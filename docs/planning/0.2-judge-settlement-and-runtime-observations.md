# 0.2 judge settlement and runtime observations

## Outcome and budget

This batch advances the roadmap's first
[product delivery checkpoint](../roadmap.md#product-delivery-checkpoints): a real,
qualified Linux plain-text rewrite that works offline after setup. It closes
supporting persistence, runtime observation, and file-input boundaries. It does
not by itself complete that end-to-end workflow.

External spending remains $0 against the same $20 development-round ceiling.
Development uses existing local tools, cached native test images, and synthetic
fixtures. The [current-state document](../current-state.md) remains the authority
for implemented behavior.

## Acceptance requirements

| Component | Required behavior and evidence |
| --- | --- |
| Managed judge cohort settlement | Derive the exact seven-record cohort from the successfully executed live Active judge join; verify same operation subject, execution identity, complete Prepared scope, sealed target ledger, retained case material, exact deterministic parents, atomic persistence and canonical cold readback; preserve replay, ordering, cancellation, deadline, and every independent finalizer |
| Unreviewed runtime observations | Launch and observe through the existing managed lifecycle, complete cleanup and package revalidation, then release canonical native-load and managed-final records preserving the observed cloud-review status; do not derive Passed controls or bypass the separate reviewed-only path |
| Retained CLI file reads | Use held regular-file handles for bounded reads, reject FIFO substitution without blocking on Unix, recheck named and held identity and file state, refuse indirect directory-input paths, and preserve the explicit single-file link and standard-input behavior |
| Public runtime evidence composition | Extend the privileged, networkless Linux controlled-build fixture to compile, publish and cold-reacquire inert admission evidence through an actual retained synthetic source-build lease; verify cancellation, existing-destination refusal, exact member bytes and tamper detection |

Synthetic fixtures cannot establish real model use, semantic fidelity, production
cloud-disable review, runtime admission, model qualification, or release readiness.
The runtime observation route must preserve `Unreviewed` rather than treating
successful observation as approval. Cleanup and package revalidation are separate
mandatory checks even after the primary operation fails.

tests and doctests, repository policy and Markdown lint. Run Linux native fixture
composition under explicit native enforcement, with network disabled and cached
images. Recheck the 80 percent Rust line-coverage floor after integration. Record
actual results and unavailable release gates separately.
