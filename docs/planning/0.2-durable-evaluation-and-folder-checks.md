# 0.2 durable evaluation and folder checks

## Purpose and budget

This batch continues the [evidence closure and CLI batch](0.2-evidence-and-cli-batch.md)
with three independent components. External spending remains $0 against the same
$20 development-round ceiling. Implementation and fixtures use local tools and
existing contracts; no paid service or model is required.

The [current-state document](../current-state.md) remains the authority for
implemented behavior. The requirements below do not establish runtime admission,
generation qualification, activation, or a release claim.

## Components and acceptance

| Component | Result | Required evidence |
| --- | --- | --- |
| Deterministic evaluation settlement | Persist exact target and baseline receipt sets and their deterministic evaluation through the live Active operation | Same operation subject, exact systems and repetition, sealed target ledger, retained case material, independent canonical readback, cancellation and deadline precedence, and every mandatory live finalizer |
| Initial runtime evidence publication | Compile and publish one bounded fixed evidence tree whose foundation is rederived from a retained byte-identical source-build closure | Exact members and manifest, immutable bounded byte snapshots, source/destination separation, staging verification, durable synchronization, no-replace publication, cold readback, and fresh source validation |
| Paired-folder candidate checks | Check supplied candidates against source documents by exact relative path in a read-only directory dry-run | Bounded deterministic discovery, exact counterpart matching, visible unmatched and skipped paths, safe reports, shared byte budget, per-document validation, cancellation, and unchanged inputs |

The runtime publisher establishes the bytes and source-build relationship of an
inert evidence root. The other control, execution, review, and policy members remain
opaque at that boundary. Their presence does not establish successful execution,
passed semantic controls, review approval, or policy authority.

The existing managed runtime verifier requires reviewed cloud-disable policy, and
the production policy is empty. Initial evidence publication must not circumvent
that requirement or substitute synthetic fixtures for the real candidate's
admission evidence.

Deterministic settlement must preserve valid failed evaluations as evidence rather
than converting them into success. Partial durable receipt-set commits can remain
after later evaluation or finalization failure, but they remain inert. Subsequent
recovery must distinguish those rows from complete qualification.

Folder checks extend the existing supplied-candidate workflow. They do not generate
candidates, write accepted documents, select models, or introduce new formats.
