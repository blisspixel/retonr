# 0.6 agent tool, MCP, and Agent Plugins execution plan

## Status and outcome

Status: planned. It depends on stable-enough application and machine contracts,
while protocol conformance research and packaging fixtures may proceed earlier.

The phase outcome is one local application service exposed consistently through the
reference CLI, MCP, Agent Skills, a portable Agent Plugin package, and optional
authenticated loopback transports. Equivalent requests and authority produce
equivalent outcomes, reasons, digests, and rewrite records through every supported
surface.

Retonr is a plugin author and MCP server. It does not build a plugin client,
marketplace, installer, updater, hosted service, or general agent framework in 1.0.

Agent packaging remains thin. It contains no rewrite, profile, model, format, or
validation logic. Broader network exposure, remote credentials, and hosted operation
remain outside the 1.0 boundary.

## Standards baseline

The research baseline reviewed on August 12, 2026 is:

- Agent Plugins 1.0.0, published as a Working Draft
- Agent Skills filesystem specification and reference validator
- MCP 2026-07-28 stateless request model
- Official Rust MCP SDK `rmcp` 3.1.2 as the implementation candidate
- Official MCP conformance prerelease containing the frozen 2026-07-28 requirements

Every version and digest is revalidated at phase entry and release freeze. A label
such as `latest` is never a build or conformance input. The exact research commits,
schema digests, corrections, and primary sources are in
[Agent integration research](../research/2026-08-12-agent-integrations.md).

## Development dependencies

- The CLI machine contract, application outcomes, profile schemas, cancellation,
  resource budgets, and document capabilities are stable enough for thin adapters.
- Shared deterministic conformance fixtures run without a real model.
- Routine rewrite authority is separable from profile read, profile mutation,
  learning, model lifecycle, and administration.
- The selected Agent Plugins schemas, Agent Skills validator, MCP revision, Rust SDK,
  and conformance requirements are pinned by exact identity.
- Package distribution, signature, installation, update, containment, and rollback
  policy is drafted independently from package format validity. External publication
  requires the applicable authorization and review.

## Required decisions

Accept architecture decisions for:

- Shared wire data transfer object ownership and schema generation
- CLI machine-contract and compatibility freeze policy
- Minimal agent tool names, inputs, outputs, limits, and authority
- Exact MCP revision, Rust SDK features, transports, and named clients
- Agent Skills content, activation testing, and compatibility metadata
- Agent Plugins package layout, schema pin, distribution, signature, and update
- Routine and privileged plugin separation
- Local API authentication, token storage, scopes, operations, and cancellation
- MCP HTTP authorization profile and documented conformance exclusions
- Compatibility adapter target, eligible response paths, byte-splicing, provenance,
  and status side channel

Skills over MCP remains an in-review optional extension and is not a 1.0 dependency.
Tasks, MCP Apps, broad prompts, resources, sampling, and roots also remain absent
unless a later measured need earns an independent decision and gate.

## Shared integration contract

Every request carries explicit:

- Request and operation IDs
- Authenticated local principal where the transport supports one
- Authority scopes
- Deadline and cancellation token
- Resource budget and network policy
- Interface, schema, protocol, and capability identity
- Profile, format, strategy, runtime, and artifact selection
- Trace and raw-content policy

The canonical domain outcomes are:

- Rewritten
- Unchanged
- Abstained
- Unsupported
- Cancelled
- Failed

Abstention is a successful protected product outcome, not a transport error. Parsing,
protocol, authorization, resource, and operational failures remain typed failures.
No agent receives candidate tokens, unvalidated output fragments, prompts, profile
evidence, or hidden traces.

Wire and domain types remain separate. JSON Schema 2020-12 artifacts are generated
from one reviewed source, checked in, compatibility-diffed, and tested against
positive and malicious fixtures. External objects are closed and bounded.

## Logical work order

### 1. Build the cross-interface conformance runner

- Feed equivalent owned requests through the in-process service and CLI.
- Compare status, stable reasons, output bytes, source and output digests, profile
  version, protected values, format state, model provenance, and redacted record.
- Normalize only documented request and transport metadata.
- Cover rewrite, unchanged, abstention, unsupported, cancellation, deadline,
  malformed input, resource limits, authorization, backend failure, and drift.
- Use deterministic fakes and network-denied execution.

Every later adapter must join this runner before it can make a support claim.

### 2. Freeze the agent-facing CLI contract

Define configuration precedence as safe built-in defaults, user configuration,
explicit configuration file, environment, command arguments, and a non-overridable
security ceiling. Restrictive policy is deny-wins.

The agent-facing CLI provides:

- Versioned capability and schema discovery
- Complete bounded input through standard input or explicit reviewed document bytes
- Protocol-clean standard output and diagnostics on standard error
- Stable exit categories and structured domain outcomes
- Deadline and cancellation behavior
- No prompts in non-interactive mode
- No arbitrary path, clipboard, model-lifecycle, profile-mutation, or administration
  authority in the routine command

Process fixtures cover PowerShell, Bash, Zsh, and Fish where supported, plus pipes,
Unicode, hostile controls, broken pipes, executable discovery, working directories,
signals, cancellation, and exact installed release binaries on all three operating
systems.

### 3. Define the minimal MCP tool surface

The routine server initially exposes only `rewrite` and `check` for complete bounded
plain text and supported Markdown values. DOCX bytes join only after the format and
byte-transfer contract passes. Arbitrary local paths, clipboard access, raw audio,
model installation, profile mutation, learning, and administration are absent.

Tool input and output schemas are closed, bounded, and versioned. One successful
result contains a checked structured outcome and compatibility text content where
required. Tool descriptions and annotations are untrusted metadata and grant no
authority.

### 4. Implement MCP 2026-07-28 over standard input

- Pin the reviewed `rmcp` version and minimal feature set.
- Implement required per-request protocol version and client-capability metadata.
- Implement deterministic `server/discover` and recognized result types.
- Treat connection and process identity as neither a session nor a principal.
- Read and write one newline-delimited UTF-8 JSON-RPC message per line.
- Reserve standard output for protocol frames and serialize all writes.
- Bound bytes, nesting, schemas, queues, concurrency, response size, and execution.
- Handle cancellation and standard-input closure without a late result or mutation.
- Return abstention as a successful structured tool outcome.
- Reject unsupported versions and missing required metadata with exact protocol
  behavior.

The implementation does not advertise capabilities, notifications, extensions, or
transports without complete fixtures.

### 5. Validate MCP standard input

Run product-owned wire and process fixtures for discovery, list, call, schemas,
results, Unicode, malformed messages, duplicate in-flight IDs, ordering, oversized
frames, saturation, cancellation, broken pipes, shutdown, crash, and restart.

Run applicable official requirements for the exact frozen revision. A passing
interactive Inspector run supplements but does not replace automated conformance.

### 6. Package the routine Agent Skill

- Write one trigger-oriented `SKILL.md` that explains when to rewrite or check.
- Describe rewritten, unchanged, abstained, unsupported, cancelled, and failed
  outcomes accurately.
- Tell the agent to preserve the user's disclosure choices and original on
  abstention.
- Keep validation, style rules, credentials, user content, absolute paths, and
  executable helpers out of the package.
- Avoid scripts unless a measured cross-platform requirement justifies them.
- Pass the Agent Skills reference validator and activation, non-activation, hostile
  instruction, failure, and recovery fixtures.

Experimental `allowed-tools` metadata is never an authorization boundary.

### 7. Assemble the portable routine Agent Plugin

The Agent Plugins 1.0.0 working-draft package contains:

```text
retonr/
|-- plugin.json
|-- skills/
|   `-- rewrite/
|       `-- SKILL.md
`-- mcp.json
```

- Pin canonical checked-in `plugin.json` and `mcp.json` schemas by digest.
- Select the same Agent Plugins schema version in both files.
- Use one bare `retonr` executable token and separate arguments for MCP standard
  input. Do not use a shell command or per-platform wrapper.
- Include no credential, token, profile, model, user content, absolute user path,
  remote endpoint, or secret-like header.
- Validate manifest, immediate-child skill discovery, component isolation,
  environment variables, placeholder expansion, and command tokenization.
- Resolve every package path and reject symlink, junction, reparse-point, alternate
  data stream, special-file, or traversal escape at the specified narrow boundary.
- Prove validation, inspection, installation, and discovery execute no code and make
  no network request.

Package containment is not a process sandbox. The release layer separately owns
source, signatures, digests, installation, updates, anti-rollback behavior, and exact
CLI compatibility because Agent Plugins defines none of them.

### 8. Run named-client compatibility

Start from clean installations and record exact client version, operating system,
architecture, supported plugin components, executable lookup, tool naming, consent
presentation, cancellation, structured result behavior, and failure handling.

Test success, unchanged, abstention, unsupported input, cancellation, malformed
input, missing executable, model unavailable, and version skew. A compatible-client
directory entry or schema-valid package is not test evidence.

Publish no claim broader than the retained matrix. A client that supports skills but
not MCP, or MCP but not plugin packaging, remains a separately described path.

### 8A. Spike Open Knowledge Format export

After the CLI, profile, brief, research-claim, support-matrix, and agent schemas are
stable enough to project, test exact Open Knowledge Format 0.2 compatibility.

- Pin one official OKF 0.2 specification revision and fixture set by digest.
- Export research claims and support combinations first, then a redacted
  profile-policy view that contains no raw samples, embeddings, credentials,
  authorization state, private paths, or short content hashes.
- Keep canonical JSON and SQLite authoritative. An OKF bundle is a view or exchange
  artifact, not a database, transaction log, or authority source.
- Preserve unknown frontmatter keys and body bytes during a no-change round trip.
- Treat `generated`, `verified`, trust tiers, status, sources, links, executors,
  attesters, computations, and code blocks as untrusted data.
- Execute and fetch nothing during validation, import, inspection, or indexing.
- Require an independent preview and authenticated transaction before any imported
  proposal affects a profile or rule.
- Compare portability and agent navigation against the versioned JSON export.
- Keep import and Attested Computation support experimental until path, YAML,
  privacy, provenance, authorization, sandbox, and reproducibility gates pass.

Agent Plugins, MCP, and OKF solve different problems. Agent Plugins packages Skills
and MCP discovery. MCP invokes live typed operations. OKF exchanges inspectable
knowledge. Passing one conformance suite does not imply support for either of the
others. The complete boundary is in
[Open Knowledge Format and Retonr](../research/2026-08-12-open-knowledge-format.md).

### 9. Add the privileged profile package only after scopes stabilize

Routine installation must not grant profile access. A separate package or separately
launched server may expose profile reads, profile mutation, learning, model lifecycle,
or administration only after those CLI contracts and scopes are stable.

Privileged operations require explicit installation and launch authority, stronger
confirmation, bounded expiring handles where needed, and application-level
authorization. Skill text, client prompts, plugin metadata, and process presence do
not grant the scope.

### 10. Implement the explicit local service lifecycle

Only now add `serve` for consumers that cannot launch a subprocess:

- Start only through an explicit command and bind to an actual loopback address.
- Reject non-loopback configuration before socket creation.
- Require a high-entropy local token and separate authority scopes.
- Validate Host and every present Origin before application work.
- Apply body, schema, queue, concurrency, deadline, response, and operation limits.
- Keep health and capabilities authenticated and content-redacted.
- Cancel on deadline or disconnect and never stream candidate text.
- Use opaque principal-scoped operation resources for work that outlives one request.
- Shut down without partial profile mutation or output commit.

Localhost is an authority boundary. Another process or web page is not trusted merely
because it can reach the port.

### 11. Implement the preview local API

Publish capability, rewrite, check, profile, operation, and administration resources
only as their authority and conformance fixtures pass.

Transport and domain outcomes remain distinct. Typed transport failures use RFC 9457
problem details. Successful domain outcomes use a versioned envelope. Every response
uses no-store policy. Conditional mutation and principal-scoped operation IDs provide
idempotency and concurrency control.

The API accepts content or a separately approved staged-document handle. It never
accepts arbitrary caller-supplied local paths. It binds only to loopback in 1.0.

### 12. Add MCP Streamable HTTP

Implement only after MCP standard input and the local service pass:

- Modern POST-only behavior for the pinned 2026-07-28 revision
- Required protocol, method, and name headers with exact body agreement
- JSON or request-scoped SSE response according to the standard
- Response-stream closure as cancellation
- No legacy GET stream, protocol session ID, sticky session, resumable event ID, or
  HTTP+SSE compatibility endpoint
- Origin, Host, bearer token, scope, redirect, cache, slow-reader, queue, and
  accidental external-binding tests

The custom loopback bearer profile is documented separately from official MCP OAuth
authorization conformance. Every supported named client must prove it can supply the
required authorization.

### 13. Run official and product HTTP conformance

Pin the conformance prerelease that contains the frozen 2026-07-28 requirements. Do
not substitute the older stable package or a floating npm tag. Run every applicable
scored server scenario with no expected failures, retain non-scored results for
visibility, and add Retonr's stricter authority, bounds, cancellation, redaction,
origin, host, and cross-interface fixtures.

### 14. Build the completed-response compatibility adapter

This adapter is a local post-processor, not an outbound proxy:

- Pin the exact upstream response schema and eligible ordinary-text paths.
- Accept only complete bounded non-streaming payloads.
- Make no model-provider request and accept no upstream credential.
- Reject malformed or oversized input with no payload.
- Return exact original bytes for unsupported valid content, abstention, or final
  verification failure.
- Treat tools, structured output, reasoning, refusals, citations, annotations,
  signatures, images, audio, and unsupported events as unsupported.
- Splice only approved JSON string ranges, reparse the complete payload, and validate
  the pinned schema.
- Preserve upstream IDs, usage, and fingerprints while recording that they describe
  the original response.
- Emit a separate local status and rewrite record with original and rewritten
  digests, schema, eligible paths, adapter, validator, and outcome identities.

A same-shape payload alone cannot communicate local abstention or provenance safely.

### 15. Freeze and publish contracts

- Compatibility-diff CLI JSON, MCP schemas and behavior, skill content, Agent Plugin
  manifests, API schemas, and compatibility response fixtures on every change.
- Publish exact schema, protocol, client, executable, and package ranges.
- Include complete examples that work with outbound network access blocked.
- Bind signed CLI and plugin artifacts to the same source revision with independent
  digests.
- Revalidate after any standard, SDK, schema, conformance package, named client,
  tool, scope, command, package, or distribution change.

## Agent Plugin invariants

- One released package has exactly one root `plugin.json`.
- Root `plugin.json` and `mcp.json` use the same supported schema revision.
- Skills are immediate children of `skills/` and directory names match frontmatter.
- Routine packaging exposes only routine rewrite and check authority.
- The stdio command is one token and arguments remain separate.
- Package content contains no credential, user data, model data, remote endpoint, or
  executable helper.
- Package paths remain inside the resolved root on every supported operating system.
- Independent component failures stop at the narrowest specified boundary.
- Loading a package never executes code or accesses the network.
- A package update passes signature, digest, schema, containment, compatibility, and
  named-client gates before activation.

## MCP invariants

- Every modern request carries the exact protocol revision and client capabilities.
- `server/discover` reports deterministic supported versions and capabilities.
- Every successful modern result carries a recognized result type.
- Connection identity is never used as principal, session, profile, or operation
  state.
- Standard output remains protocol-only under every success and failure.
- Cancellation emits no late result and commits no late mutation.
- Tool schemas are closed, bounded, and validated before model work and release.
- Domain abstention and protocol failure remain distinct.
- No untested capability, extension, notification, transport, or legacy behavior is
  advertised.

Overall implemented Rust line coverage remains at least 80 percent. Protocol parsing,
authorization, cancellation, operation state, package containment, schema validation,
and compatibility splicing target at least 90 percent line coverage with every
material branch represented.

## Exit evidence

The phase closes only when:

- CLI, MCP standard input, the Agent Skill, and the routine Agent Plugin agree on the
  shared deterministic corpus.
- Applicable official MCP requirements and product conformance pass for the exact
  pinned revision.
- Named-client claims match clean-install evidence on the declared platforms.
- Routine installation grants no privileged authority.
- Package inspection and execution add no hidden network access, credentials, source
  content, or independent product logic.
- Optional loopback API and MCP HTTP claims pass their separate security and
  compatibility gates.
- All refinement passes complete with no open critical protocol, authority, privacy,
  compatibility, packaging, or fidelity defect.

The handoff to 0.7 includes stable document-byte boundaries, a portable agent package,
named-client evidence, and one application contract that DOCX can join without
granting arbitrary path authority.
